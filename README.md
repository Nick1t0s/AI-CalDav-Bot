# AI-CalDav-Bot

Telegram-бот для управления Яндекс-Календарём (и любым CalDAV-сервером) на агентной архитектуре:
интеллектуальный ассистент понимает запросы естественным языком, умеет читать, создавать, изменять
и удалять события — а все изменения выполняет ТОЛЬКО после явного подтверждения кнопкой.

Примеры запросов:

- «что у меня завтра» — покажет события завтрашнего дня;
- «что у меня на следующей неделе» — события за период;
- «удали ближайшее вычесывание бобров» — сам найдёт нужное событие и предложит удалить;
- «перенеси занятие завтра на 20:00» — изменит событие (с превью и подтверждением);
- «перенеси тренировку на 19:00 и создай встречу с Аней в 20:00» — несколько действий за одну команду;
- «создай встречу с Аней завтра в 14:00 на час» — создаст событие (с подтверждением);
- «отмени завтрашнее занятие» / «перенеси юайти на час позже» — работает и с повторяющимися событиями;
- для повторяющихся событий спросит: «удалить одно вхождение или всю серию?»;
- поддерживает голосовые сообщения: распознаёт речь (STT) и обрабатывает как обычный текст.

## Как это работает

Бот построен на агентной архитектуре: LLM (нейросеть) разбирает естественный язык и планирует
действия через function calling. Используются 4 инструмента:

| Инструмент | Что делает |
|---|---|
| `get_period` | **read-only** — читает календарь за период и возвращает компактный каталог событий (серии одной строкой) |
| `reg_list` | **staged** — накапливает список изменений (создание/удаление/исключение вхождения/обновление) в план сессии |
| `ask_user` | задаёт пользователю уточняющий вопрос (с кнопками-вариантами), цикл ставится на паузу до ответа |
| `done` | завершает ход: финальный ответ + накопленный план |

**Ключевой принцип безопасности: LLM планирует, скрипт исполняет.**

- Нейросеть может ТОЛЬКО читать календарь и копить план изменений — она никогда не пишет
  в календарь напрямую.
- Накопленный план показывается человеку списком с кнопкой **«✅ Выполнить всё / ❌ Отмена»**.
- Реальные изменения (создание/изменение/удаление) выполняет обычный код через CalDAV —
  строго после нажатия кнопки подтверждения.
- План живёт 15 минут (TTL); новое сообщение пользователя отменяет висящий неподтверждённый план.

### Повторяющиеся события

- Обнаружение серии: наличие `RRULE` в VEVENT.
- «Удалить только одно вхождение» → в мастер-событие добавляется `EXDATE`;
  «удалить всё» → `event.delete()`.
- «Изменить только одно вхождение» → `EXDATE` + новое отдельное событие (`exclude` + `add`);
  «изменить всё» → правка мастер-события (`update_event`, UID сохраняется).
- При переносе недельной серии на другой день недели `BYDAY` правило повтора обновится автоматически.

## Стек

- [aiogram 3](https://docs.aiogram.dev) — Telegram Bot API (async, long polling, inline-кнопки);
- [caldav](https://caldav.readthedocs.io) + [icalendar](https://icalendar.readthedocs.io) — протокол CalDAV;
- [recurring-ical-events](https://pypi.org/project/recurring-ical-events/) — раскрытие повторяющихся событий (RRULE/EXDATE);
- [openai SDK](https://pypi.org/project/openai/) — агент с tools (`base_url` настраивается:
  OpenAI, OpenRouter, локальный vLLM и т.д.; провайдер должен поддерживать function calling);
- [python-dotenv](https://pypi.org/project/python-dotenv/) — конфигурация.

Требуется **Python 3.12+**.

## Установка

### Локально (venv)

```bash
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt

cp .env.example .env   # затем отредактируйте .env
```

### Docker

```bash
cp .env.example .env   # затем отредактируйте .env
docker compose up -d --build
```

Контейнер читает переменные окружения из `.env` (через `env_file`) — монтирование томов не нужно:
приложение stateless, все данные хранятся в CalDAV.

Просмотр логов и остановка:

```bash
docker compose logs -f
docker compose down
```

## Настройка .env

Скопируйте шаблон: `cp .env.example .env`. Ниже — все переменные.

### 1. Telegram

| Переменная | Обязательна | Описание |
|---|---|---|
| `BOT_TOKEN` | да | Токен бота от [@BotFather](https://t.me/BotFather) (см. ниже) |
| `ALLOWED_USER_IDS` | да | ID разрешённых пользователей через запятую. Пусто = доступ запрещён всем |

**Как получить токен бота:** напишите [@BotFather](https://t.me/BotFather) → `/newbot` →
укажите имя и username → скопируйте токен вида `123456789:AAE...` в `BOT_TOKEN`.

**Как узнать свой user_id:** напишите боту [@getmyid_bot](https://t.me/getmyid_bot) или
[@userinfobot](https://t.me/userinfobot) → он пришлёт ваш числовой ID. Впишите его в
`ALLOWED_USER_IDS`. Если пользователей несколько — через запятую: `111111,222222`.

### 2. CalDAV (Яндекс Календарь)

| Переменная | Обязательна | Описание |
|---|---|---|
| `CALDAV_URL` | да | Адрес CalDAV-сервера. Для Яндекса `https://caldav.yandex.ru` |
| `CALDAV_USERNAME` | да | Полная почта, например `you@yandex.ru` |
| `CALDAV_PASSWORD` | да | App password типа «Календарь» (см. раздел ниже), НЕ обычный пароль |
| `CALDAV_PRINCIPAL_PATH` | нет | Запасной путь к principal, если `client.principal()` не сработает |
| `CALENDAR_PATH` | нет | Прямой URL конкретного календаря |
| `CALENDAR_ID` | нет | Выбрать календарь по имени (иначе берётся первый не-«Корзина») |

`TZ=Europe/Moscow` — часовой пояс, в котором бот показывает время.

### 3. LLM (агент)

| Переменная | Обязательна | Описание |
|---|---|---|
| `OPENAI_API_KEY` | да | Ключ API |
| `OPENAI_BASE_URL` | нет | Базовый URL. Пусто = официальный OpenAI. Примеры: `https://api.openai.com/v1`, `https://openrouter.ai/api/v1`, `http://localhost:8000/v1` (локальный vLLM) |
| `OPENAI_MODEL` | нет | Модель (по умолчанию `gpt-4o-mini`; для OpenRouter — `openai/gpt-4o-mini`) |
| `OPENAI_THINKING` | нет | `enabled` (по умолчанию) / `disabled`. `disabled` отключает «мышление» модели — отсылаются `reasoning.enabled=false` и `thinking.type=disabled` (для DeepSeek, где reasoning включено по умолчанию) |
| `REQUESTS_TIMEOUT_SECONDS` | нет | Таймаут HTTP-запросов к LLM (по умолчанию 60) |
| `LOG_LEVEL` | нет | `INFO` (по умолчанию) / `DEBUG` — печатает весь диалог модели перед каждым вызовом LLM |

Параметры агента:

| Переменная | По умолчанию | Описание |
|---|---|---|
| `AGENT_MAX_STEPS` | `8` | Максимум итераций цикла агента на сообщение |
| `AGENT_SESSION_TTL_MIN` | `30` | Время жизни сессии-диалога (минуты) |
| `AGENT_HISTORY_LIMIT` | `30` | Обрезка истории сообщений, уходящих модели |
| `AGENT_CATALOG_LIMIT` | `50` | Лимит строк каталога событий, отдаваемого модели |
| `LIST_DEFAULT_DAYS` | `90` | Окно поиска (дней вперёд) для запросов «что у меня есть»/«когда <событие>» без явной даты |

### 4. STT (голосовые сообщения)

Распознавание работает через OpenAI Whisper API и требует **отдельный** ключ OpenAI, если
`OPENAI_BASE_URL` указывает на провайдера без аудио-эндпоинта (OpenRouter, vLLM):

```env
STT_API_KEY=sk-...                # если пуст — используется OPENAI_API_KEY
STT_BASE_URL=https://api.openai.com/v1
STT_MODEL=whisper-1
STT_LANGUAGE=ru
```

## Подключение Яндекс Календаря: как получить App password

Яндекс не принимает обычный пароль для CalDAV — нужен **пароль приложения**:

1. Войдите в свой аккаунт на Яндексе.
2. Откройте раздел паролей приложений:
   https://id.yandex.ru/security/app-passwords
   — если страницы нет или она пуста, сначала включите **двухфакторную аутентификацию**
   (https://id.yandex.ru/security) — без неё пароли приложений не выдают.
3. Нажмите **«Создать пароль»**.
4. Выберите тип приложения **«Календарь»**.
5. Скопируйте сгенерированный пароль вида `xxxx-xxxx-xxxx-xxxx`.
6. Вставьте его в `.env`:
   ```env
   CALDAV_URL=https://caldav.yandex.ru
   CALDAV_USERNAME=you@yandex.ru
   CALDAV_PASSWORD=xxxx-xxxx-xxxx-xxxx
   ```

Этот пароль даёт доступ только к календарю и не открывает вашу почту.

## Подключение другого CalDAV-провайдера

Бот работает с любым сервером CalDAV: достаточно указать его адрес и креды.
Для большинства провайдеров это буквально одна строка — `CALDAV_URL` (и соответствующие
логин/пароль/token). При проблемах с автоопределением используйте `CALDAV_PRINCIPAL_PATH`,
`CALENDAR_PATH` или `CALENDAR_ID`.

| Провайдер | `CALDAV_URL` | Логин | Пароль |
|---|---|---|---|
| Яндекс Календарь | `https://caldav.yandex.ru` | полная почта | App password (тип «Календарь») |
| iCloud | `https://caldav.icloud.com` | Apple ID | App-specific password (сгенерировать в appleid.apple.com → Security → App-Specific Passwords) |
| Nextcloud | `https://ваш-сервер/remote.php/dav/` | логин | обычный пароль / app password |
| Radicale / Baikal (self-hosted) | `https://ваш-сервер/` или свой путь | логин | пароль |
| Zimbra | `https://ваш-сервер/dav/` | логин | пароль |

> ⚠️ **Google Calendar** по логину/паролю не подключается: Google не отдаёт личный CalDAV
> по простым кредам, нужен OAuth2-доступ — это вне рамок текущего бота.

Если календарь не находится автоматически (варианты):

```env
# Прямой URL календаря (перекроет автоопределение):
CALENDAR_PATH=https://caldav.yandex.ru/.../your-calendar/

# Или выбрать календарь по имени из списка:
CALENDAR_ID=Личный
```

## Отладка

- `LOG_LEVEL=DEBUG` в `.env` — печатает весь диалог с моделью (JSON), каждый шаг агента
  (`AGENT chat=... шаг=N ...`), вызовы инструментов. Шумные логгеры сторонних библиотек
  приглушаются автоматически.

## Ограничения

- Сессии диалогов, планы и вопросы живут in-memory: перезапуск бота теряет незавершённые
  диалоги и ожидающие подтверждения.
- Провайдер LLM должен поддерживать function calling (tools) — не все локальные vLLM умеют.
- Долгие операции перезаписи календаря выполняются синхронно в отдельном потоке: при очень
  большом календаре история ограничивается `AGENT_CATALOG_LIMIT` и `AGENT_HISTORY_LIMIT`.
